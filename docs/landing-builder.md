# Конструктор лендингов

Лендинг собирается из готовых блоков. Организатор меняет тексты, картинки, порядок, тему и варианты отображения.
Свободной вёрстки и прямого HTML нет: страница всегда корректна на телефоне, а блоки с данными не устаревают.

## Редактирование

Структурное, как у стандартных блоков Tilda или в Notion.

1. **Текст на превью.** Заголовки и подписи правятся кликом прямо на странице.
2. **Панель настроек блока.** Форма строится автоматически по схеме блока: поля, картинка с кадрированием, вариант отображения, переключатели, повторяющиеся элементы с перетаскиванием.
3. **Форматированный текст.** Tiptap с урезанной панелью: жирный, курсив, ссылка, списки, подзаголовок. Без цветов, размеров и HTML.

Интерфейс: слева список блоков (перетаскивание, скрыть, удалить, добавить), в центре превью в iframe (телефон и десктоп), справа настройки выбранного блока. Черновик, публикация, история версий, откат.

## Схема блока

Одна схема описывает форму в редакторе, проверку на сервере и рендер:

```js
export default defineBlock({
  type: 'hero',
  title: 'Обложка',
  variants: ['image-bg', 'image-right', 'text-only'],
  props: {
    title:     { type: 'text',  inline: true, max: 80 },
    subtitle:  { type: 'text',  inline: true },
    image:     { type: 'image', ratio: '16:9' },
    cta:       { type: 'cta',   default: 'registration' },
    countdown: { type: 'bool',  label: 'Таймер до конца приёма заявок' },
  },
  data: ['event.dates', 'event.place', 'registration.window'],
})
```

Сайт хранится как JSON: страницы → список блоков `{ id, type, variant, props, common }` + тема.
Сервер валидирует props по схеме (JSON Schema генерируется из `packages/blocks`).

## Общие настройки любого блока

- якорь и пункт меню;
- фон из темы: обычный, приглушённый, акцентный;
- правило показа: всегда, только во время приёма заявок, только после публикации итогов.

## Публикация и домены

- Публикация фиксирует версию сайта; `sites` рендерит её по Host, кэш в Redis сбрасывается при публикации.
- SEO: title, description, OG-картинка, sitemap, robots, ID Яндекс.Метрики.
- Поддомен `<slug>.events.skolhub.ru`: wildcard DNS + один wildcard-сертификат (DNS-01).
- Свой домен: организатор добавляет домен → инструкция с CNAME → проверка DNS → worker пишет файл в динамическую конфигурацию coolify-proxy (роутер на Host, certresolver HTTP-01) → статус «активен».
- Форма регистрации на лендинге обращается к API с другого домена: CORS по списку подтверждённых доменов. Вход в кабинет всегда на `app.events.skolhub.ru`.
